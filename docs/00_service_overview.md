# 00. 서비스 개요

## 배경

부산광역시 × 코리아크레딧뷰로(KCB) 공동발제 해커톤(DIVE 2026). 주제: 부산 청년 1인가구 경제 안정성 진단과 데이터 기반 맞춤형 정책 추천 솔루션 개발.

## 문제 정의

```
주거비 부담 상승 → 카드·대출 의존 증가 → DTI/상환부담 상승
   → 단기 연체 → 신용점수 하락 → 더 비싼 금융·주거 선택지로 밀림 (악순환)
```

부산시는 이미 청년월세지원, 머물자리론, 기쁨두배통장 등 다수의 청년 정책을 보유하고 있다. 문제는 정책의 부재가 아니라 **정책과 대상자 간의 매칭 지연 및 배정 비효율**이다. 부산청년플랫폼에는 이미 AI 정책 추천 메뉴가 있어 단순 추천 챗봇으로는 차별화가 안 된다.

## 핵심 차별화 관점

"어떤 정책이 있는지 모른다"가 병목이 아니라 **"한정된 예산으로 누구를 먼저 지원해야 전체 위험도가 가장 많이 줄어드는가"**가 진짜 병목이다. 이건 추천 문제가 아니라 **배정 최적화 문제**다.

| 구성요소 | 일반적 해커톤 접근 | 우리 접근 |
|---|---|---|
| 위험 유형 정의 | 사람이 사전에 N개 유형을 정의 | GMM으로 유형 수·경계를 데이터에서 추정 |
| 위험 시점 | 이진 분류(연체 여부) | 생존분석(연체까지 남은 기간) |
| 정책 배정 | if-else 룰 테이블 | 예산 제약 하 선형계획법(LP) |
| 운영 중 개선 | 없음(정적 모델) | Thompson Sampling 기반 지속 학습 |
| 설명 | 정적 템플릿 문구 | SHAP + LLM 기반 개인화 자연어 설명 |
| 데이터 신뢰성 | 결측치 무시 또는 일괄 삭제 | 컬럼 그룹별 결측 진단 프레임워크 |

## 제품 구성

| 제품 | 대상 | 플랫폼 |
|---|---|---|
| **청년야호** (서브타이틀: "위기가 오기 전에, 먼저 압니다") | 부산 청년 1인가구 (시민) | Android 네이티브 (Kotlin Compose) |
| **Y-SAFE 대시보드** | 부산시 행정 담당자 | 웹 (React) |
| 공통 백엔드 | - | FastAPI + PostgreSQL + Redis |

네이밍 전략: 시민 접점은 친근하게("청년야호"), 행정 접점은 전문적으로("Y-SAFE")라는 톤 분리를 의도적으로 사용한다.

## 제공 데이터 (당일)

- KCB 신용정보: 신상/소득/자산/대출/카드/연체 관련 약 42개 컬럼 (`data/column_spec.xlsx` 참고)
- 현재는 5행짜리 샘플만 존재 (`data/sample.csv`) — 실제 데이터가 아니므로 값 자체보다 **구조/컬럼명/결측치 표현방식**을 참고용으로만 사용
- 외부 공공데이터(선택, 가점용): 국토교통부 실거래가, 부산시 생활인구 데이터, 행정동 경계 데이터
