# 06. 설명 에이전트 (Layer 4)

## 목적

"왜 이 순서로 이 정책을 추천했는지"를 개인화된 자연어로 생성. 템플릿 if-else 문장이 아니라 실제 수치 기반 생성이 핵심 차별점.

## 입력 스키마

```json
{
  "shap_top3": [
    {"feature": "주거가격부담률", "impact": 0.34},
    {"feature": "추정DTI", "impact": 0.21},
    {"feature": "소득증감률", "impact": -0.15}
  ],
  "cluster_membership": {
    "주거비압박형": 0.62,
    "부채과부하형": 0.31,
    "기타": 0.07
  },
  "assigned_policies": ["청년월세지원", "희망신용상담센터"],
  "hazard_ratio_context": {"주거가격부담률": 1.8}
}
```

## 프롬프트 설계 원칙

- 낙인 문구 금지: "당신은 고위험군입니다" 같은 표현 대신 "이번 달 먼저 신청하면 좋은 정책"처럼 행동 지향적 문구.
- 수치를 그대로 노출하지 말고 자연어로 풀어서 설명 (예: "impact 0.34" → "주거비 부담이 다른 요인보다 크게 작용했어요").
- 응답 길이: 3~4문장 이내로 제한 (앱 UI 카드에 들어갈 분량).
- Claude API 호출 시 시스템 프롬프트에 위 원칙을 명시.

## 구현 위치

`layer4_explanation/explanation_agent.py` — Claude API 호출 래퍼, 입력 스키마 검증, 프롬프트 템플릿 관리

## API 연동

앱의 "왜 추천했는지" 화면에서 요청 시 실시간 호출 (`GET /api/v1/citizen/{session_id}/explanation`). 응답은 세션에 캐싱해 동일 세션 재요청 시 재호출하지 않음 (Redis 캐시 활용).
