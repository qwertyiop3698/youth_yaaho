# 02. 데이터 결측치 처리 프레임워크 (Layer 0) — 필독

이 문서는 Layer 0 구현 전에 반드시 읽어야 한다. 결측치 처리를 컬럼 전체에 일괄 규칙으로 적용하면 안 된다.

## 전제와 톤

샘플 CSV(`data/sample.csv`)는 5행짜리 발제 측 목업이지 실제 KCB 데이터가 아니다. 여기서 발견한 특성(-99999999 sentinel 등)을 "실제 데이터의 확정된 특징"으로 단정하지 말 것. "이럴 가능성에 대비했다"는 리스크 대응으로 구현하고, 당일 실제 데이터를 받으면 프로파일러부터 재실행한다.

## 확인된 사실: 같은 "0"도 컬럼마다 의미가 다르다

샘플 데이터 분석 결과:

| 값 | 컬럼 예시 | 실제 의미 |
|---|---|---|
| 0 | 증빙연소득 (5행 중 3행이 0) | 명세상 "증빙자료 없음"을 뜻하는 정상 비즈니스 값. 결측 아님 |
| 0 | 대출연체건수, 카드연체건수 | "연체 없음"이라는 정상 값. 결측 아님 |
| 0 | 차량보유(국산/수입) | "차량 없음"으로 추정되는 카테고리 코드. 결측과 구분 필요 |
| -99999999 | 2년내현거주지평균실거래가/전세거래가 | 국토부 실거래가 매칭 실패로 추정되는 sentinel. 결측 처리 대상 |

**결론: 컬럼 전체에 "0=결측"이나 "0=정상"을 일괄 적용하지 않는다. 컬럼별 판단표(아래 4번)를 반드시 참조한다.**

## 추가 확인 사실: 데이터 스펙과 실제 제공 컬럼의 불일치 가능성

- 엑셀 명세(`data/column_spec.xlsx`)엔 `거주지행정동`, `근무지행정동` 컬럼이 있는데, 샘플 CSV엔 `거주지 시군구 코드`, `근무지 시군구 코드`만 존재함 (명세상 이 컬럼들은 "열 삭제" 처리 대상이었음에도).
- 즉 **외부데이터(국토부 실거래가, 생활인구) 조인 시 행정동 키가 없을 수 있다는 전제로 설계**해야 한다. → 조인은 행정동 우선 시도, 실패 시 시군구코드로 fallback하는 이중 조인 로직 구현.
- 성별(1/2), 직업군(420/910), 자가거주여부(3), 차량보유(0) 등 정수 코드가 코드북 없이 옴. 실제 데이터에 코드북이 별도로 오는지 당일 확인 필요. 안 오면 범주형은 원-핫 대신 빈도 인코딩/타겟 인코딩으로 처리해 코드 의미를 몰라도 모델이 작동하게 한다.

## 자동 컬럼 프로파일러 (구현 필수)

당일 실제 데이터가 들어오면 컬럼 전체(42개+)를 사람이 눈으로 훑을 시간이 없다. 다음 기능을 하는 프로파일러를 구현한다.

### 기능 1: 결측 후보 자동 탐지
- Sentinel 패턴: 절댓값이 해당 컬럼 정상범위(예: IQR 기반)의 1000배 이상인 극단값이 반복 등장하는지 스캔
- Null/NaN 직접 결측
- 범주형: 사전 정의된 코드북 범위를 벗어난 값(unknown code)

### 기능 2: 0-값 의미 분류
- 컬럼을 그룹(신상/소득/자산/대출/카드/연체/기타)으로 분류하는 매핑 테이블을 설정 파일로 관리 (`config/column_groups.yaml`)
- 그룹별로 0이 "자연스러운 카테고리"(대출/카드/연체 등, 없음=0이 정상)인지 "이상한 카테고리"(신용평점, 자산평가금액 등)인지 사전 정의
- 애매한 경우(예: 추정월소득=0)는 별도 플래그로 표시 후 사람이 확인하도록 리포트에 하이라이트

### 기능 3: 결측 비율 리포트 자동 생성
- 컬럼별 결측 후보 비율, 0비율, 유니크값 수를 표로 출력 (`profiling_report.json` / `.md`)
- 당일 이 리포트부터 5분 안에 확인하고 대응 우선순위를 정하는 워크플로우 전제

## 컬럼 그룹별 처리 전략

| 컬럼 그룹 | 결측/이상값 판단 기준 | 처리 전략 | 근거 |
|---|---|---|---|
| 신상정보 (성별/연령대/직업군 등) | 코드북 외 값 = unknown | 최빈값 대체 대신 "unknown" 카테고리로 유지 | 범주형 임의 대체는 편향 유발 |
| 소득정보 (추정월소득/증빙연소득 등) | 증빙연소득=0은 정상. 추정연소득=0/음수는 이상 | 증빙연소득 0은 유지+"증빙없음" 플래그 컬럼 추가. 추정연소득 이상값은 KNN 또는 median 대체 | 0의 의미가 컬럼마다 다름 |
| 자산/주거 (총자산평가금액, 실거래가 등) | sentinel(-99999999) 등 극단값 | 자동탐지 후 지역 평균/중앙값 대체 + `_was_missing` 플래그 컬럼 추가 (행 삭제 지양) | 명세는 "행삭제"지만 소량 데이터에서 표본손실 큼 |
| 대출/카드/연체 (건수, 금액) | 0 = 정상(거래없음) | 결측 아님, 그대로 사용 | 확인된 사실 |
| 추정모형항목 (LTV/DTI/신용평점) | 대출 없으면 LTV/DTI=0 정상. 신용평점 0/저평점은 Thin Filer 여부와 교차 확인 | LTV/DTI는 그대로, 신용평점은 별도 로직 | Thin Filer=1이면 신용평점 산출 자체가 안 됨(명세 명시) |
| 라이프패턴 (2년내 직장명이력건수 등) | 0 = 정상(이직 없음) | 결측 아님 | |

## 구현 원칙

1. **원본값 삭제 금지**: 모든 결측 처리는 원본을 지우지 않고 별도 `_was_missing` 플래그 컬럼을 추가한다. 결측 자체가 신호일 수 있다 (예: 실거래가 매칭 실패 자체가 거주지 정보 불안정성을 의미할 수 있음). 모델이 이 플래그를 함께 학습하게 한다.
2. **처리 전/후 분포 비교 리포트 자동 생성**: 발표 자료용 근거 확보.
3. **최소 표본 미달 시 계층적 fallback**: 특정 그룹(예: 특정 행정동)의 표본이 너무 적으면 상위 카테고리(시군구)로 자동 백오프.
