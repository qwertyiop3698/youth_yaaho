# Y-SAFE 파이프라인 전체 실행 결과 요약

- 실행일: 2026-07-11
- 목적: Layer 0~4 전체 파이프라인이 실제로 끝까지 동작하는지 검증
- 입력 데이터:
  - Layer 0만: `data/sample.csv` (발제 측 목업, 5행) → `data/processed/`
  - Layer 0~4 전체: `data/synthetic_large.csv` (파이프라인 스트레스테스트용 합성데이터, 1500행) → `data/processed_large/`
- **주의**: synthetic_large.csv는 실제 KCB 데이터가 아니라 `backend/scripts/generate_synthetic_large_dataset.py`가 numpy 분포로 처음부터 생성한 합성 데이터. sample.csv에서 파생된 게 아니라 컬럼명/일부 지역코드만 sample.csv를 참고했을 뿐, 값 자체는 무관함. 따라서 아래 결과의 **수치/클러스터 프로파일 자체는 실제 정책적 의미가 없고, "파이프라인이 실규모에서 안 죽고 동작하는가"를 검증하는 용도**로만 봐야 함.

## Layer 0. 데이터 계약 & 결측치 진단

**5행 sample.csv 실행 결과** (`data/processed/`):
- 42컬럼 → 정제 후 59컬럼(`_was_missing` 등 플래그 컬럼 추가)
- sentinel(-99999999) 탐지 정상 작동: "2년내 현거주지평균실거래가"(4/5행), "2년내 현거주지평균전세거래가"(5/5행 전부)에서 검출
- **엣지 케이스 발견**: "2년내 현거주지평균전세거래가"는 5행 전부가 sentinel이라 지역→시군구→전체 median 백오프를 다 시도해도 대체할 정상값이 하나도 없어 대체값이 `null`로 남음. 에러 없이 이 상태 그대로 리포트에 남기는 것까지 확인.
- config(`column_groups.yaml`)엔 있는데 데이터엔 없는 컬럼 4개(`거주지행정동` 등) 자동 탐지 확인 → 스펙-실데이터 불일치 대응 로직이 실제로 작동함

**1500행 synthetic_large.csv 실행 결과** (`data/processed_large/`):
- 동일 로직이 실규모에서도 정상 동작
- 연체 관련 5개 컬럼(`대출연체건수` 등)이 `leakage_columns`로 정확히 식별됨 → Layer 2-B의 데이터 누수 방지 assert가 참조하는 목록

## Layer 1. 피처 엔지니어링

- clean_dataset(59컬럼) → featured_dataset(**78컬럼**, 1500행)
- 파생변수 14개 + 도메인지수 5종(주거비압박/부채상환위험/소득변동성/소비압박/신용취약) 정상 계산
- `연체심각도`는 `diagnostic_only_features`로 명시적으로 격리되어 예측모델 피처 목록에서 제외되는 것을 코드 레벨(`get_diagnostic_only_features()`)로 확인
- 5행 실행 시엔 "z-score 표준화: 표본 부족(n=5<20)" 경고가 반복 발생 — 통계적으로 불안정할 수 있음을 코드가 스스로 인지하고 경고하는 방어 로직

## Layer 2-A. GMM 소프트 클러스터링

- 5행에서는 표본 부족(n=5<30)으로 **자동 스킵**됨 (`model_trained: false`) — 정상적인 방어 동작
- 1500행에서는 K=3~10 × covariance(full/diag) 16개 조합을 모두 학습·비교
  - **BIC 기준 최적: K=7, diag** (BIC=9690, 최저)
  - **실루엣 기준 최적: K=3** (silhouette=0.284, 최고)
  - → BIC와 실루엣이 불일치하는 실제 사례 발견. 발표 시 "BIC를 1차 기준, 실루엣으로 교차검증" 식의 방법론적 근거로 활용 가능
- 사전 가설 6개 유형 중 "Thin Filer형", "자산형성가능형"은 실제 클러스터에서 관측 안 됨. 대신 가설에 없던 "신용취약형"이 2개 클러스터(1, 6)에 걸쳐 등장 → `suggested_labels`에 "가설 목록 밖 - 사람 확인 필요"로 자동 플래그됨
- 클러스터 규모(soft assignment 기대값 합): 423명(소비유동성위험형) ~ 32명(부채과부하형, 소비압박지수 -2.29로 극단치 소그룹)까지 다양

## Layer 2-B. 위험 예측 모델

### ⚠️ 중요: 문서(docs/04)와 실제 구현이 다른 지점

`docs/04_modeling_clustering_survival.md`는 **Cox 비례위험모형을 주모델**로 설계했지만, 실제 코드(`cox_trainer.py`)는 **비활성 스텁 상태**임. 코드에 남은 결정 기록(2026-07-08):

> KCB 데이터가 단일 시점 크로스섹션 스냅샷이라 duration(사건까지 남은 시간)을 관측할 방법이 없음. 검토한 대안 3가지(연체일수를 경과기간으로 근사/위험도 기반 합성 duration/duration 없이 event만 예측) 중 앞의 둘은 각각 "시간 방향이 反대"·"순환논증"이라는 이유로 기각하고, **"duration 없이 event(이진 라벨)만 예측"으로 채택**. 실제 패널/시계열 데이터가 확보되면 `train_cox_model()`을 구현하도록 인터페이스만 남겨둠(호출 시 `NotImplementedError`).

**현재 주모델**: 로지스틱회귀 vs LightGBM 이진분류를 학습해 held-out PR-AUC로 자동 선택 + 확률 보정(CalibratedClassifierCV).

**1500행 실행 결과**:
- event 양성비율: 16.2%
- 로지스틱 PR-AUC 0.224 vs LightGBM PR-AUC 0.194 → **로지스틱 회귀 선택** (baseline 0.162 대비 소폭 개선)
- AUC-ROC는 0.55~0.57 수준 — 합성데이터가 무작위성 위주라 신호가 약한 게 정상(실데이터에서는 개선 기대)
- Spatial CV(행정동 기준 5-fold): PR-AUC 0.21~0.34로 폴드 간 변동은 있으나 전체적으로 정상 작동
- 공정성 감사: 성별 간 AUC 차이 존재(남 0.60 vs 여 0.71), 연령대 70/75세는 표본 부족(n<20)으로 자동 스킵 — 계획된 방어 로직 확인
- SHAP top3 및 확률 보정 모두 정상 산출, `risk_model.pkl`엔 배포용 보정모델 + SHAP 전용 원본 LightGBM을 분리 저장

## Layer 3. 최적화 엔진

**LP 예산 배정** (1500명 × 6개 정책):
- 최적해(Optimal) 도출, 총 684건 배정, 1인당 최대 2개 정책
- 예산 10%↑당 평균 커버리지 증가분: 2.9%p

**Thompson Sampling 시뮬레이션** (2000라운드):
- 정책별 사후평균이 숨겨진 true_effectiveness에 상당히 근접 (예: 청년월세지원 사후 0.758 vs 실제 0.75)
- 구간별 평균 regret이 초반 0.037 → 중반 0.0057 → 후반 0.0027로 **단조 감소** — 밴딧이 실제로 학습(수렴)하고 있음을 정량적으로 확인
- prior(LP 초기 가정치) vs true_effectiveness 격차표: 6개 정책 중 3개는 과소평가, 3개는 과대평가로 방향이 고르게 분산 → "밴딧이 틀린 가정을 교정한다"는 데모 설득력 확보

## Layer 4. 설명 에이전트

- `ANTHROPIC_API_KEY`가 이 환경에 설정돼 있지 않아 Claude API 실제 호출은 실패
- 다만 이게 바로 설계된 **폴백 체인**이 작동하는 걸 확인하는 계기가 됨: `explanation_service.generate_explanation()`이 API 실패를 감지 → 로그 경고 남기고 → SHAP 템플릿 기반 설명으로 자동 전환 (`is_llm_generated=False`)
- 위험확률 최상위 인물(사람 351, 위험확률 0.756, 신용취약형 cluster_6에 100% 소속, 배정 정책 "청년디딤돌카드 플러스")에 대해 실제로 생성된 템플릿 설명:

  > "최근 신용 점수이(가) 다른 요인보다 크게 작용했어요. 이번 달 먼저 신청하면 좋은 정책은 청년디딤돌카드 플러스이에요. 지금 미리 준비해두면 상황이 더 어려워지기 전에 도움을 받을 수 있어요."

  → 낙인 문구 없음, 수치 미노출, 3문장 이내 — 문서(docs/06) 원칙 그대로 충족.

## 종합 결론

1. **Layer 0~3 전 구간이 5행/1500행 모두에서 에러 없이 끝까지 실행됨.** 표본 부족 시 자동 스킵(Layer 2-A), sentinel 전량 결측 시 null 허용(Layer 0) 등 방어 로직이 실제로 작동.
2. **문서와 구현이 갈라진 지점 1건**: Cox 생존분석은 설계 문서상 주모델이었으나, "duration을 관측할 수 없다"는 현실적 이유로 2026-07-08에 로지스틱/LightGBM 이진분류로 대체 결정됨. 발표 자료가 여전히 Cox를 주모델로 설명하고 있다면 업데이트 필요.
3. **Layer 4는 실제 LLM 호출 없이 폴백 경로만 검증됨.** 해커톤 당일 데모 전에는 `ANTHROPIC_API_KEY`를 설정하고 실제 Claude 응답 품질도 확인 필요.
4. 클러스터링(Layer 2-A)에서 BIC와 실루엣이 다른 K를 가리키는 지점, 사전 가설에 없던 유형이 발견된 지점은 발표 스토리("가설과 실제를 대조했다")에 그대로 활용 가능한 소재.
